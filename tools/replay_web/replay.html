About replays

  

    
What a replay can and cannot tell you

    
    
      
  • Same recordings, not the same result to the digit. The camera file holds the pictures the live camera kept (about 14 a second). On playback the programs take the ones they keep up with, so the number of saved places, loop closures and the tracking figure differ a little from the drive, and two replays of one drive also differ a little.
    • 
      
  • Start from a parked moment. The first ~5 s of the camera recording play before the camera and the wheel recording are brought exactly into step. Every drive starts parked for a minute, so replaying from the start of a camera file is fine.
    • 
      
  • Depth is worked out again on playback. Any depth mode can be tried, but the result is not identical between runs; self-calibration is frozen to remove one cause.
    • 
      
  • Only what the camera file covers can be replayed. Some drives have two camera files, each covering part of the drive.
    • 
      
  • Normal speed only. The camera software plays its file by the clock on the wall, so the wheel recording must too.
    • 
      
  • One replay at a time, and never while the robot is driving: both would slow each other down.
    • 
      
  • Comparing with the drive: the numbers say how well the replay agrees with the original drive. Neither is the true path, so a difference is not an error of either one.
    • 
      
  • Bench test: a recording without the sphere target stand finds no target; it only shows the depth recomputation and the measurement run.
    • 
    

    
Words used

    

      
SLAM, RTAB-Map
SLAM builds a map while working out where the robot is in it. RTAB-Map is the SLAM program used here.

      
fusion.bag
A time-stamped log of the robot's wheel distances and gyroscope (turn sensor).

      
.svo2
The ZED X camera's own recording: both stereo pictures of every frame. Distance is worked out again on playback.

      
depth mode
The camera software's method for working out distance (NEURAL, NEURAL_PLUS, QUALITY, ULTRA, PERFORMANCE): trade-offs between accuracy and computing time.

      
loop closure
The map recognising a place it has seen before and pulling itself back into line.

      
robot's own tracking / after the map's corrections
The camera's step-by-step tracking, never corrected, against the map's answer after its loop closures. Both are shown, never mixed.

      
back at the start
How far the path's end is from its start. The drives end where they began, so a small number is good.

      
agreement with the original drive
The typical distance between the replay's path and the drive's path, after turning and shifting one onto the other (no stretching).

      
sphere target, centre, wobble
The bench stand holds three balls; the centre is their middle, measured in every frame: how far ahead and how far to the side. The wobble (standard deviation, mm) says how much it moves between frames.

      
depth stabilisation
A filter that smooths depth over several frames. Off makes two replays of one file identical; on matches the live camera.

    

  







Times are Hamilton time. Replays run on the Jetson at low priority and never touch a live drive.
