# Results - one folder per run

This folder holds the small result files for every run of the project: numbers, trajectories, maps drawn as pictures, and charts. Each run has its own folder, grouped by kind:

- `series1_august/` - the August lab-room runs (series 1); only run 8's trajectories are kept here.
- `series2_static/` - series 2 (24-27 Sept 2026): the mapping drives `s2_static_01` to `s2_static_10`, the localisation sessions (`s2_loc_*`: the robot is put on a map it built earlier and must work out where it is), the taped distance test (`s2_scale_01`) and the parked sensor-blending rehearsal (`s2_fusion_T4b`).
- `series2_slam/` - SLAM (simultaneous localisation and mapping: building the map while using it) on top of an earlier map.
- `navigation/` - autonomous driving to goals on the saved map of the whole floor.

Most run folders have a `RESULTS.md` (the run's results pack) whose first section carries the headline numbers; every number in it names the file it came from.

**Two kinds of start-to-end gap.** Most drives start and end on the same floor mark, so the distance between the first and last position shows how far the estimate drifted. It is always reported in two labelled kinds, never mixed on one axis:
- *tracking alone* - read from the map database's `Node.pose` table: where the step-by-step tracking (odometry) put each map snapshot, never corrected. In the fused drives (drive 3 onward) this is the position of the blend (the camera mixed with the robot's wheels and gyroscope, a turn-rate sensor), not the camera alone.
- *corrected* - where the map puts the robot after its loop closures (the map recognising a place it has seen before and pulling itself straight), read from `Admin.opt_poses` (the corrected positions RTAB-Map, the mapping program, saves when it shuts down properly) or re-computed from the saved links when that table is empty. A corrected gap is always given with its loop-closure count, because a closure that joins the end straight to the start makes the gap small by construction.

**Wording rule for the LiDAR comparison.** The LiDAR trajectory (from a colleague's LiDAR mapping on the robot; LiDAR = a laser scanner that measures distance) is **agreement with an independent LiDAR estimate, never error against ground truth**. Its own uncertainty: LiDAR range noise 15-30 mm, and the mounting offset between the LiDAR and the camera was never measured. When the LiDAR estimate fails its own check (it must end within 0.5 m of its start with at least one LiDAR loop closure), the agreement figure measures the LiDAR's drift as much as the camera's and is shown only for information. Agreement figures are the median distance between the two paths after lining them up once by rotation and shift, with no scaling.

## Recurring file names in a run folder

| file | what it is |
|---|---|
| `RESULTS.md` | the run's results pack: every number with the file it came from |
| `camera.tum` | map snapshots' tracking-alone positions (`Node.pose`). TUM format = one line per position: time, x, y, z and orientation as a quaternion (a 4-number way to store a rotation) |
| `camera_corrected.tum` | the same snapshots' corrected positions (`Admin.opt_poses`, or re-computed; its `.meta.json` says which, and the closure count) |
| `lidar.tum` | the LiDAR estimate's corrected positions, from the robot's LiDAR map database |
| `wheel.tum` | the robot's own wheels + gyroscope estimate (`/odometry/filtered`), taken from the robot's LiDAR recording |
| `*.meta.json` | how each `.tum` was made: source, tool, pose count, gaps |
| `facts.json`, `map_corrected_facts.json`, `lidar_map_facts.json` | the floor map built from tracking-alone, corrected, or LiDAR positions: node count, duration, path length, start-to-end gap, map size |
| `agreement.json`, `lidar_comparison/` | camera-vs-LiDAR agreement (median, 95th percentile, largest, matched share); the folder holds the aligned paths, per-path results and plot data |
| `numbers.json`, `paths_2hz.csv` | figures from the drive's full sensor recording (gaps, headings, path lengths, lost stretches); positions of every source sampled twice a second |
| `map.png`, `map_corrected.png` | the floor map drawn from tracking-alone and from corrected positions [not verified: inferred from the matching facts files] |
| `lidar_map.png`, `trajectory.png`, `lidar_comparison.png`, `turns_difference.png` | LiDAR floor map; paths; camera over LiDAR (LiDAR solid, camera dashed); per-turn heading differences |
| `turns.csv`, `turns_replayed.log` | every turn: degrees turned by robot, camera and blend; the log is the turn watcher's rule replayed over the recording after the drive |
| `freezes_pass_check.json` | camera-freeze check: camera silences over 1.5 s, picture-loop pauses over 2 s, long database saves, and a verdict |
| `power_temperature.json` | peak and median power and chip temperatures from tegrastats (NVIDIA's once-a-second load log) |
| `timelapse_25/50/75/100.png`, `timelapse_live_index.csv` | frames of the live map page at 25, 50, 75 and 100 % of the drive [not verified: inferred from the names]; index of every captured frame with time and tracking state |
| `closed_check.txt`, `db_check.txt` | whether the map database was closed properly (corrected positions saved); database integrity check |
| `provenance.txt`, `products.log` | how and from what the pack was made |
| `map_3d/`, `lidar_ref_f3dof/` | a 3D point-cloud export of the map (a picture and notes; the point cloud itself is not here); the flat-floor LiDAR replay's files |

Raw recordings (.svo2 camera files, .db map databases, .bag recordings) and the timelapse videos are not in this repository; they are in the Autonomous Service Robot Microsoft Teams folder (ask Prof. Moein Mehrtash for access) - see data/DATA_INDEX.md.
